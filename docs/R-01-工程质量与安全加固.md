## 需求与验收标准

本需求针对当前项目审查发现的 CI 覆盖不足、请求边界不完整、内容同步可靠性和配置弃用问题。分阶段交付，每个阶段独立验证。

### 本期范围边界

- 保留当前 Memos 0.29 的 URL query token 鉴权，不改现有 webhook 鉴权兼容逻辑。
- Memos 升级到 `v0.30.0+` 后迁移 Standard Webhooks 签名，作为下一份需求单独登记。
- 本期只处理 webhook 请求体大小、错误记录和输入校验等不改变现有鉴权方式的优化。

- AC-1：WHEN 提交或 PR 触发 GitHub Actions，系统 SHALL 执行格式检查、Astro 检查、静态构建和 Functions 类型检查；IF 任一检查失败，THEN 工作流 SHALL 失败。
- AC-2：WHEN 访问受保护的内容写入、内容删除和图片上传接口，系统 SHALL 拒绝缺少有效会话或 Bearer 凭据的请求；IF 请求路径、请求体或文件元数据超出约束，THEN 系统 SHALL 返回 4xx 且不写入 R2。
- AC-3：WHEN 接收 Memos webhook，系统 SHALL 保持当前签名或 URL query token 的兼容鉴权行为；IF 鉴权或请求体校验失败，THEN 系统 SHALL 拒绝请求且不修改内容桶。
- AC-4：WHEN Memos webhook 或内容 API 接收请求体，系统 SHALL 在读取或写入前执行大小上限校验；IF UTF-8 字节数超过上限，THEN 系统 SHALL 返回 413。
- AC-5：WHEN 内容同步脚本执行，系统 SHALL 使本地 `src/content/` 与 R2 中 `posts/`、`notes/`、`pages/` 三个前缀的 markdown 集合一致；IF R2 中已删除文件，THEN 本地构建目录 SHALL 不再保留该文件。
- AC-6：WHEN 内容写入成功但 Deploy Hook 触发失败，系统 SHALL 记录可检索错误；IF 发布未触发，THEN API 响应 SHALL 明确表示内容已保存但发布待重试。
- AC-7：WHEN 图片上传包含多个变体，系统 SHALL 限制单文件、总请求体、变体数量、尺寸和格式；IF 任一约束失败，THEN 系统 SHALL 拒绝整个请求且不留下不完整的变体集合。
- AC-8：WHEN 静态站响应页面和动态接口响应，系统 SHALL 输出约定的安全响应头；IF CSP、HSTS 或其他必需头缺失，THEN 安全验收 SHALL 不通过。
- AC-9：WHEN Astro 构建运行，系统 SHALL 使用当前支持的 Markdown processor 配置；IF 构建日志仍出现已弃用 Markdown 配置警告，THEN 配置迁移验收 SHALL 不通过。
- AC-10：WHEN 执行项目测试命令，系统 SHALL 覆盖路径校验、会话签名、Webhook 鉴权、内容大小限制和限流边界；IF 任一核心安全用例失败，THEN CI SHALL 失败。

### 入参约束

- markdown 内容：保持现有单文件上限 1 MB，按 UTF-8 字节数计算。
- 内容路径：只允许 `posts/`、`notes/`、`pages/` 前缀和 `.md` 后缀；禁止空段、路径逃逸和未允许的控制字符。
- Memos webhook：上限 256 KB，不包含图片上传请求；继续兼容当前签名和 URL query token。
- 图片：单次请求总上限 32 MB，最多 12 个变体，单文件上限 10 MB，格式保持 webp/jpeg。

## 设计要点

- CI：在 `.github/workflows/ci.yml` 中增加 `pnpm typecheck:functions`，并新增测试命令作为独立步骤。
- 测试：优先抽取纯函数测试；Cloudflare 绑定相关逻辑通过最小 mock 验证，避免为单元测试引入真实 D1、R2 或外部服务。
- Webhook：本期不迁移鉴权方式，保留签名校验和旧版 query token；增加请求体大小限制和失败日志。Standard Webhooks 签名迁移另立需求，避免影响当前已调通链路。
- 内容 API：集中复用路径和 UTF-8 大小校验，避免内容写入、Webhook 写入和图片上传各自维护不同规则。
- 内容同步：同步到临时目录后按前缀替换，或在确认目录范围后清理旧文件，避免删除内容残留在本地构建结果中。
- 发布触发：`triggerDeploy` 不再静默吞掉错误；接口响应区分「内容已保存」和「部署已触发」。是否增加重试/队列取决于部署平台能力。
- 安全响应头：优先使用 Cloudflare Pages `_headers` 配置静态响应头；CSP 默认不允许第三方资源，动态接口补充必要的缓存和内容类型策略。
- Astro：引入并固定 `@astrojs/markdown-remark`，通过 `markdown.processor` 迁移现有 `rehypeMedia`，保持 Markdown 输出行为不变。
- 影响范围：涉及 CI 配置、Functions 鉴权与输入校验、R2 内容同步、Cloudflare Pages 响应头、Astro 构建依赖和测试依赖；不新增数据库表，不改变内容 frontmatter 格式。

## 已确认结论

- Memos 签名迁移不属于本需求，待升级到 `v0.30.0+` 后另立需求；本期固定保留 URL query token。
- webhook 请求体上限为 256 KB，不包含图片上传请求。
- 图片单次请求总上限为 32 MB，最多 12 个变体，单文件上限为 10 MB。
- 测试使用 Node 原生测试能力，不引入浏览器测试框架。
- Deploy Hook 本期不做自动重试，只记录错误并返回明确状态。
- CSP 不允许第三方评论、统计或图片资源；后续如引入第三方资源，需先更新 spec。
